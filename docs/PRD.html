Claim Chart Refinement, PRD

Draft v1

Problem Statement

Analysts get an AI-drafted first pass of a claim chart, and it's usually not good enough to send out as-is. Sometimes the evidence is just marketing copy dressed up as proof, sometimes the reasoning is too thin to survive a claim construction fight, and every so often the AI just misses something or points at the wrong part of the product. Right now the only way to fix any of that is manual editing in whatever doc tool they're using, which throws away the one thing the AI is actually good at: re-reading the source material and re-arguing the point when you tell it what's wrong. I wanted a chat layer on top of the chart that lets an analyst say "this is weak, fix it" and get something better back, without ever letting the AI quietly rewrite something it shouldn't.

User Stories

  • Pick one claim element and ask the AI to make the evidence stronger, instead of re-researching it by hand.
  • Push back when the AI cites the wrong thing, and have that actually stick.
  • Undo a change I didn't mean to accept, without losing everything else I did that session.
  • Have the AI tell me "I don't have anything to back this up" instead of making something up that sounds fine.
  • Set a posture once ("be conservative here") and have it hold for the rest of the session.
  • Never have the chart change underneath me. I want to see the suggestion before it's real.

Core Features

Setup is three short steps: upload the claim chart, optionally add product docs the AI can cite, set instructions for how it should behave. Each upload step has a little file browser with a preview so you're not picking blind. After that you're in the workspace: pick a row, ask for what you want in plain language, and the AI comes back with a specific proposed change to either the evidence or the reasoning, never both, never silently. You accept it, reject it, or edit it yourself before it goes in. Every row keeps its own undo history. If the AI can't back up a claim from what's uploaded, it says so and asks for a doc or a URL instead of guessing. Export produces a real .doc file with the current state of the chart.

In scope

  • 3-step setup with file preview before you commit to anything
  • You can add or remove reference docs at any point, not just at setup: header, chat, a card in the workspace, wherever's convenient
  • Each claim element has its own separate conversation. More on why below.
  • AI proposes one specific change at a time, tied to accept/reject/modify
  • Undo goes back through the full history of a row, not just one step
  • You can deselect a row, or wipe the session and start over, both with a confirm step
  • Confidence tag (strong/moderate/weak) that the AI keeps up to date on its own
  • Real Word-compatible export, not a fake success toast

Out of scope

  • No real LLM call. Responses are scripted/deterministic so the demo is reproducible
  • No real file parsing. Local upload sits in the UI but is inert, and says so, rather than pretending to work
  • If you ask the AI to add a whole new row it wasn't tracking, it'll ask you for details instead of just inserting one. Didn't want silent chart edits, even well-intentioned ones
  • No multi-user, no auth, nothing collaborative
  • No whole-chart-at-once editing from one prompt. Every request is scoped to a row on purpose
  • Export isn't citation-formatted or litigation-ready, just a clean readable doc

Key Decisions

Scoping every request to one row instead of the whole chart

I went back and forth on this. Letting someone type one prompt and have it touch the whole chart is faster, but it's also exactly how you get a change nobody asked for buried in row 6. Analysts already think about these charts element by element, so matching that felt safer than it felt slow.

Nothing the AI says ever writes to the chart directly

This is the one I wouldn't compromise on. The output here ends up in a legal filing, so the AI is a drafting assistant, not an editor with commit access. Accept/reject/modify on literally everything, even if that's an extra click every time.

The AI has to say "I don't have evidence for this" out loud

Left to its own devices, a model asked to "strengthen the evidence" will usually find a way to sound confident even when the underlying material is thin. That's the actual failure mode I was most worried about here, more than it giving a bad answer: it giving a plausible-sounding bad answer. So weak rows get flagged proactively, and if there's nothing to point to, it says so and asks for a source instead of reaching.

Each element gets its own chat thread

Honestly, this one wasn't in my original plan, I found it as a bug. Early on, switching the selected row only updated the label at the top; the actual conversation underneath stayed put, so you'd be looking at element 1's chat while the header said element 3, and "undo" would quietly apply to whichever row was actually selected. In a normal app that's an annoying paper cut. In something feeding a legal document, that's an analyst approving a change while looking at the wrong context, which is a real problem, not a UX nitpick. Once I saw it happen I redid the state so each row's conversation is fully isolated instead of being one shared list I'd have to keep filtering correctly.

Acceptance Criteria

  • Given a weak row, if you ask to strengthen it and there's nothing uploaded that could help, the AI has to ask for a source, not invent one.
  • An AI proposal never touches the chart until you explicitly accept or confirm an edit. Reject leaves it untouched and asks what's wrong.
  • Accepted changes can be undone per row, and the chat says what got reverted.
  • If you tell it a citation is wrong and give it the right quote, the chart reflects your quote, not the AI's original one.
  • The chart updates in place after every accepted change. No reload, no losing your spot.

Success Metrics

  • Time to get a weak row to strong via chat, compared to doing it by hand. This is the whole pitch, so it should show up here.
  • Accept/modify rate on AI proposals. If people are rejecting outright a lot, the suggestions aren't good enough yet.
  • How often analysts have to correct the AI's evidence. This is really a proxy for how good the underlying retrieval is, not a UX metric.
  • Undo rate. If it's high, the accept step isn't doing its job as a real checkpoint.

Assumptions

Written under a 24-hour window with no ability to ask clarifying questions, so a few of these are guesses I'd want to validate with a real analyst before building further:

  • Assumed one active claim chart at a time is fine for v1. Didn't build anything for managing multiple charts or patents in parallel.
  • Assumed analysts would rather see the AI decline to help than get a confident-sounding guess. I'd want to confirm that trade-off doesn't just shift the work back to them too often.
  • Assumed "add a new row" should stay a manual, reviewed action rather than something the AI can do from chat. Felt like the safer default, but it's a real UX cost if it comes up a lot in practice.
  • Mocked the LLM entirely for this prototype. The conversational patterns (row-scoped requests, confidence flagging, evidence refusal) are the actual design; wiring up a real model is a separate, more mechanical problem.
